Building Monad is the **curation layer** of the public Monad knowledge system.

It does not own a second copy of the engineering record. Instead, it assembles durable records from the other publication domains into coherent reading paths that explain how the project developed and why particular moments mattered.

<Callout type="info" title="Curation, not authority">

Building Monad may summarize, sequence, and interpret material, but it does not replace the source record.

For current technical truth use [System](/docs/system). For normative and inspectable engineering records use [Artifacts](/docs/artifacts). For chronological working history use the [Engineering Journal](/journal). For externally meaningful changes use [Changelogs](/changelogs). For editorial explanation and argument use [Articles](/articles).

</Callout>

## What question does each domain answer?

| Domain | Primary question |
| --- | --- |
| [System](/docs/system) | What is true about Monad now? |
| [Artifacts](/docs/artifacts) | What was specified, decided, evidenced, reviewed, or verified? |
| [Engineering Journal](/journal) | What happened while the work was being done? |
| [Changelogs](/changelogs) | What changed at a meaningful publication or release boundary? |
| [Articles](/articles) | What should readers understand about this subject? |
| **Building Monad** | How do those records fit together into the story of the project? |

That final question is the reason this section exists.

## Four common reader paths

### New reader

Start with [Series](/building-monad/series), then read the current [System overview](/docs/system). Use the Journal only when you want the history behind a particular result.

### Architect

Start with the [Architecture phase](/building-monad/phases/04-architecture), then move into [Artifacts](/docs/artifacts) and the ADR corpus. Use Articles for interpretation and Journal entries for historical context.

### Builder

Start with [Installments](/building-monad/installments) to understand the current work context, then use [Project](/docs/project), [System](/docs/system), and the relevant specifications as the operational source of truth.

### Historian

Use the [Project Phases](/building-monad/phases) as the spine, then follow links into Journal entries, Changelog records, ADRs, requirements, and Articles to reconstruct how understanding changed over time.

## How curation works

A Building Monad page should normally do four things:

1. identify the question, theme, phase, or moment being curated,
2. explain why the selected records belong together,
3. link to the durable source records in their native domains,
4. distinguish historical interpretation from current authority.

It should **not** copy an ADR, reproduce an Article, mirror a Journal entry, or restate an entire Changelog record.

That rule keeps the public knowledge system composable: one record can participate in many narratives without creating many competing copies of the same truth.

## Governing principle

> **Building Monad should make the evolution of the project intelligible without becoming another place where project truth must be maintained.**

The source records remain where they belong. Building Monad supplies sequence, interpretation, context, and paths through them.
