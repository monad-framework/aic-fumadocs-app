# Unreleased

This page is the mutable change buffer for Monad.

Items belong here when they are meaningful enough to appear in a future changelog but have not yet crossed a publication boundary.

Unlike published changelog records, this page is intentionally editable. Items can be clarified, regrouped, removed, or moved as implementation and verification progress.

## Added

- Added a typed editorial metadata contract for public Articles, including durable publication IDs, publication type/state, byline, publish/revision dates, audiences, topics, reading time, series relationships, canonical URLs, related reading, and featured status.
- Added `/articles/format` as the public editorial lifecycle and authoring contract.
- Added the first real Blog publication, `ART-2026-08-30-001 — Why Monad Has Four Publication Domains`.
- Added `content/building-monad` and `/building-monad` as the dedicated Building Monad curation domain.
- Added `/building-monad/format` as the public curation and source-ownership contract.
- Added the first curated installment connecting the publication-domain Journal, Changelog, Article, and resulting architecture.
- Added intent-based homepage reading paths for newcomers, builders, architects, implementers, and historians.
- Added federated global search across Documentation, Journal, Changelogs, Articles, and Building Monad.
- Added domain filters and per-result epistemic cues such as current, governed, historical, release record, editorial, mutable, coordination, and curated.

## Changed

- Reworked `/articles` into an editorial publication overview rather than a generic article-folder index.
- Reworked Blog, Research, and White Papers as distinct editorial forms with different purposes and standards while retaining a shared metadata envelope.
- Article family navigation now keeps landing pages first and published work newest-first.
- Published Article pages now render editorial publication metadata above the article body.
- Expanded global Articles navigation with an Articles overview and authoring guide.
- Removed the Articles-local floating `Ask AI` control because the current AI endpoint searches authoritative docs rather than editorial content.
- Building Monad is now a curation layer that links source records owned by Documentation, Journal, Changelogs, and Articles rather than duplicating those records inside `/docs`.
- Building Monad now has explicit Series, Installment, Phase, and editorial-reading curation surfaces.
- Global navigation now exposes Building Monad as a first-class domain.
- Reworked the homepage around reader intent and the five-domain knowledge architecture instead of the older three-layer model.
- Reworked `/docs` into a focused authoritative technical entry point rather than a second general-purpose homepage.
- Reworked About around Monad's enduring thesis, boundaries, principles, and falsifiable assumptions rather than site navigation and historical record ownership.
- Reorganized global navigation into Start Here, Documentation, Building Monad, Articles, Changelogs, and Journal so the public information architecture is visible directly from the site shell.
- Global search now discovers all five public knowledge domains instead of only Documentation.
- Documentation AI is now explicitly documentation-scoped in both its prompt and trigger so broad discovery does not blur source authority.

## Fixed

- Legacy `/docs/building-monad/...` links now redirect to their top-level `/building-monad/...` equivalents, while the former Journal path continues to redirect directly to `/journal`.
- Removed stale orientation links and descriptions that treated Building Monad as a docs-owned journal/essay container or used obsolete root-relative documentation routes.

## Promotion rule

When a release, prerelease, hotfix, or notable change set is published:

1. create a dated changelog record,
2. assign it a durable `CHG-YYYY-MM-DD-NNN` ID,
3. move the applicable Unreleased items into that record,
4. record breaking and migration impact explicitly,
5. link deeper Journal or Artifact records when they materially help explain the change,
6. remove the promoted items from this page,
7. leave unrelated Unreleased work in place.

Do not use this page as an engineering task list. Work planning belongs in the relevant engineering workflow; this page tracks only changes that are candidates for public release/change communication.
